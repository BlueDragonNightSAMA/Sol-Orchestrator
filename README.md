## 插件介绍（Sol-Orchestrator）

### 核心作用
让 **Sol** 负责项目规划、核心任务和最终审查；将边界明确的任务委派给 **Terra/Luna**，从而提升并发效率并减少 Token 消耗。

---

### 执行流程
用户目标  
→ Sol 制定 1～N 个任务  
→ Sol 保留核心任务  
→ Terra/Luna 执行委派任务  
→ 每个任务写入独立结果文件  
→ Sol 逐项审查  
→ Sol 串行整合  
→ 未完成则自动生成下一批  
→ 独立复核通过后 goal_complete

<hr>


### 可配置功能

| 功能 | 可选值 | 作用 |
|------|--------|------|
| 模型 | 自定义 Sol / Terra / Luna | 填写部署的模型 ID 和接口 |
| 推理强度 | none ～ xhigh | 每个模型可独立设置 |
| 任务数量 | 1～N、0 | 0 表示 Sol 自动决定 |
| Token 模式 | economy / balanced / quality | 控制上下文与输出预算 |
| 执行方式 | auto / api-parallel / host-agents | 自动、API 并发或子对话执行 |
| 文件模式 | compact / expanded | 精简归档或保留全部过程文件 |
| 工作模式 | auto / manual / documents | 自动执行、人工配置或仅生成文档 |

**默认：`economy + compact + auto`**

<hr>


### 对话管理
- 每个子对话绑定固定的 `conversationProjectId`，禁止跨项目发送内容。  
- 对话开头示例：P0001 | terra-5.6 | 完成插件并通过测试 | T02
- 聊天窗口显示“对话队列”：包含项目编号、模型、目标、任务内容和状态。  
- 同一项目可创建 N 个子对话（属于 Codex 宿主子代理，不是独立 UI 线程）。

<hr>


### 并发与文件安全
- 无依赖任务可同时创建 N 个对话。  
- 有依赖任务按波次执行（如：T02 → T01）。  
- 每个对话拥有独立的提示文件与结果文件。  
- 子对话只能读取共享项目，不能直接修改源码。  
- 修改方案写入自身结果文件，Sol 审查通过后按顺序应用。  
- 已通过的任务不会重复执行或重复审查。

<hr>

### 长期目标
使用命令：/gaol 完成整个项目并通过全部测试
- 插件会持续保留最终目标。  
- 当前任务耗尽但项目未完成时，会调用 `continue_goal` 生成下一批任务。  
- 只有 Sol 独立复核确认完成后才返回：goal_complete

<hr>


### 文件存储结构
默认存储在当前项目目录：

sol-orchestrator-projects/
└── P0001/
    ├── PROJECT.md
    └── B01-运行编号/
        ├── run-bundle.json
        └── final-review.md

`compact` 模式仅保留主文档、合并归档与最终审查文件，减少废弃文件。

<hr>


### Token 降低策略
- Sol 优先生成较少但边界明确的任务。  
- 子模型只接收自身任务上下文。  
- 已通过任务不重复执行或审查。  
- 长期目标只传递审查摘要，不重复传递完整历史。  
- economy 模式使用本地最终汇总，减少一次模型调用。  
- 仅在并发确实有收益时增加任务数量。
